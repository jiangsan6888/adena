**登录入口**
- 正式登录链接即你的静态站点 URL：
  - GitHub Pages：`https://jiangsan6888.github.io/adena/`
  - 或 Vercel 部署域名（如 `https://your-vercel-project.vercel.app/`）
  - 或自定义域名（例如 `https://trade.example.com/`）
- 用户只访问上述前端入口；Supabase 作为后端，不直接暴露给用户。

**一次性配置注入**
- 首次在正式域名注入 Supabase 配置（之后该域名的 localStorage 会持久保存）：
  - 示例（Query）：`https://jiangsan6888.github.io/adena/?supabase_url=...&supabase_key=ey...&supabase_bucket=best`
  - 示例（Hash）：`https://jiangsan6888.github.io/adena/#supabase_url=...&supabase_key=ey...&supabase_bucket=best`
- 完成一次注入后，用户直接访问根 URL 即可登录和使用；无需再次带参。

**安全与策略**
- 仅在前端使用 Supabase anon key（ey 开头的 JWT）；不要使用 service_role。
- RLS 已为 users/games/products/servers/notifications/advertisements 开启匿名增删改查策略；如迁移到生产环境可逐步收紧。

**用户体验**
- 在站点导航的“登录”按钮作为统一入口，指向统一 URL（根 URL）。
- 页脚和帮助页给出“如无法加载数据，请刷新或重新打开带参链接”的提示。

**多环境建议**
- 开发/测试/生产使用不同子域名或项目，并各自完成一次配置注入。
- 为不同环境准备对应带参链接，避免串用配置。
